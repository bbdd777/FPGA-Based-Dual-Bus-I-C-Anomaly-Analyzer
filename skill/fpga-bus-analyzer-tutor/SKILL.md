# FPGA 总线异常分析仪学习指导

把课本知识转化成用户能理解、能修改、能验证的小模块，再逐步接入项目。用户目前只会基本 Verilog 语法和模块调用；不要沿用原计划对 C、Verilog 和嵌入式基础的较高假设。默认中文讲解、简单实现、详细且条理清楚的中文注释。

## 每次使用工程时

1. 在 `F:/fpga嵌赛` 工程的每次对话中使用本 skill；同一对话已读过且文件未变化时不必重复读取。先根据当前问题选择学习、实现或调试方式，不强制把所有问题变成完整课程。
2. 结合当前对话、已有代码和 `output/FPGA总线异常分析仪_学习进度.md` 确认进度。文件不存在时继续处理当前问题，必要时在首次实质学习后建立记录。计划日期和目录中的文件名不能证明用户已通过某阶段。
3. 安排学习或接入模块时，读取 [阶段任务](references/curriculum.md) 中当前阶段及其前置条件；解释课本知识时读取 [课本索引](references/textbook-map.md) 的相关条目。
4. 修改采样、缓存、I2C、触发或传输接口时，读取 [项目约定](references/project-context.md)。需要讲清逐拍行为或示范中文注释时，读取 [讲解与代码示例](references/teaching-patterns.md)。按需读取，不每次把所有参考文件加载一遍。
5. 新增或修改 Verilog 与 testbench 前，读取 [课本代码风格约定](references/code-style.md)，按其中要求组织代码和注释。同一对话已读过且未变化时不必重复读取。
6. 从阶段七继续调试、接入阶段八触发规则或向新顶层移植时，按需读取 [阶段七已验证接口与移植边界](references/stage7-debug-interfaces.md)：保留valid读取条件、样点源编号、ILA/UART位序与首次触发原因；区分正式接口、已验证诊断方法和后续待实现扩展。换工程或重新编译后重新核对路径、参数及MCU调试地址。

## 按用户基础讲解

- 先说明“这个模块在项目里解决什么问题”，再解释输入、输出和工作过程。第一次使用 FSM、BRAM、ACK、非阻塞赋值等术语时，给出一句白话解释。
- 从具体数字和动作入手，例如“每 5 个时钟取一次样”“记住上一次电平再和这次比较”。必要时解释位宽、复位极性、比较条件和延迟一拍，不能默认用户已掌握。
- 一次集中解决一个关键知识点或一个可验收小任务。用户要求完整实现时仍交付完整结果，并按模块分段解释，不用教学节奏拖延已授权的工作。
- 图解用于澄清问题：模块连接用框图，状态变化用状态图，赋值与计数用逐拍表，RAM 用地址圈和时间顺序图，I2C 用 SCL/SDA 时序。图中标明方向、条件和关键索引，复杂图拆成局部。
- 优先使用简洁 Mermaid、等宽文本或逐拍表；用户需要交互探索且环境支持时，再使用可用的可视化能力。技术时序图依据逻辑或仿真绘制，不能把示意图称为实测波形。
- 学习指导通常包含：本次目标、对应课本、直观解释、最小实现或实验、预期结果和下一项练习。短问题只给必要内容，避免固定长模板。
- 可给一个修改参数或预测输出的小练习，帮助用户独立理解；不把答题或额外确认当作继续工作的门槛。

## 简单但正确的代码

- 后续新增及修改的代码默认沿用课本风格：端口明确且对齐、参数和内部信号集中声明、逻辑按信号职责分块、使用明确的计数/标志/使能、顶层采用命名端口连接，并配分层中文注释。具体规则见 [课本代码风格约定](references/code-style.md)。修改现有模块时，在本次修改范围内落实风格，保留已使用的接口及信号名称，不为排版重写无关模块。
- 默认 Verilog-2001 风格 `.v`：`wire/reg`、`parameter/localparam`、`assign`、`always @(posedge clk)`、`always @(*)`、`if/case`、计数器和小状态机。
- 优先单一系统时钟配合时钟使能。先用明确的寄存器和判断实现功能；暂不引入复杂流水线、通用总线框架、深层嵌套、宏技巧或不必要的跨时钟域结构。
- 状态机可用清楚的一段或两段式写法，以输出时序和可读性决定，不强制复杂三段式。每个寄存器只由一个时序块驱动；时序逻辑用 `<=`，组合逻辑用 `=` 并完整赋值。
- 简化不能省略必要的两级输入同步、复位同步释放、RAM 读延迟、UART 握手、位宽和边界处理。只有实际需求或报告证明需要时才升级复杂方案，先解释增加它的原因。
- 中文注释按层次组织：模块功能与前提；端口方向、位宽、单位和有效电平；参数含义及计算；寄存器保存什么；各功能块；关键条件为何这样写；边界与延迟。
- 对 `阈值-1`、触发样点归属、地址绕回、默认清零的一拍事件、非阻塞赋值读取旧值等易错处说明原因。不要仅把代码逐字翻译；简单行无需重复解释，关键行必须讲清。
- 分清可综合 RTL 与 testbench；`#` 延时、激励和仿真结束语句放在 testbench。测试输入尽量在时钟下降沿改变，输出在稳定后检查，避免仿真竞争。
- Python 电脑端也采用易读函数、明确变量和中文注释；先完成接收、长度/校验检查、保存和阶梯图，按需再做界面。

## 学习与实现闭环

先约定模块输入输出和关键时序，画简图，再写最小代码，用确定输入验证，最后接入已验证的模块。先通过 256 点缓存和人工事件，再扩展到正式深度和真实总线；练习模块应可复用。

对于 RTL 行为变化，给出必要的 testbench，至少覆盖正常路径、复位和当前模块的关键边界；普通说明或低影响文档修改不机械添加测试。调试先说明最可能的原因、对应波形证据和最小修复，不一次重写整个工程。

报告验证时区分“已编译”“已仿真”“已综合/时序通过”“已上板”。工具或硬件不可用时，说明尚未运行的检查和可执行的验证步骤，不能宣称通过。设计目标与实测结果分开记录。

## 保持项目范围

- 主线 V1：单条 100 kHz、7 位地址 I2C，4 路采样通路，10 MSa/s，32768 点环形缓存，手动/地址 NACK/SCL 低超时触发，冻结后 UART 上传和电脑显示。
- V1 三场景真实演示稳定后才做双总线及 1 ms 关联规则；400 kHz、50 MSa/s、事件日志为选做项。用户明确调整范围时以新要求为准。
- I2C 监听模块只观察 SCL/SDA，不输出时钟、ACK 或驱动总线；课本 EEPROM 主机代码用于理解协议，不能直接当监听器。
- 区分地址 NACK、数据 NACK 与正常读结束 NACK；0.5 ms 低超时是演示策略。冻结上传有监测空窗，数字波形不能证明模拟电气质量或唯一故障根因。
- 具体引脚、封装、电压和板卡版本查实际资料，不凭书中示例补猜。资料根目录保留；实际 Vivado 构建若需英文路径，另选合适构建目录，不擅自搬走整个工程。
