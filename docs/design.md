# 最终工程实现说明

本说明记载最终配置与实现。后续实物结果见[实测汇总](../data/test_summary.csv)，2026年10月23日英文目录离线重建结果见[历史验证范围与本次PC更新](pc_update_20261027.md)；原文中的阶段性待测描述应结合这些后续结果阅读。


## 参数与范围

| 项目 | 实际配置 |
|---|---|
| 器件 | XC7A100T-FGG484-2，升腾Pro原阶段九引脚 |
| 时钟 | 单一50MHz，无新增采样时钟 |
| 采样 | 每拍取样，50MSa/s，20ns/点 |
| 通道 | bit0 A_SCL、bit1 A_SDA、bit2 B_SCL、bit3 B_SDA |
| 深度 | 262144点，地址18位；逻辑容量128KiB |
| 窗口 | 5.24288ms，完整窗触发索引131072 |
| 前后分配 | 严格在触发前131072点；触发点及之后共131072点 |
| 时间编号 | 64位，全工程每20ns加1；事件携带自己的源编号 |
| 低确认 | 连续25000个低样点，即名义500us，一次低区间只报一次 |
| 关联窗口 | 50000个间隔，即1ms，等于边界认可 |
| 完整读窗口 | 从B首个68/W ACK到完整读STOP不超过100000个间隔，即2ms，属于作品策略 |
| UART | 默认1,000,000 baud、8N1，只发不收，无命令/布防依赖 |

262144点相对旧32768点增加8倍，50M相对10M增加5倍，所以窗口从3.2768ms增加到5.24288ms。提高采样频率时同步增加深度，已避免“点数不变导致时间窗口缩短”的问题。这个窗口能包含多少次通信还取决于 MCU 实际安排；当前 MCU 每轮约5s，不会在5ms内自然产生5轮完整测试。

## 模块连接

```text
四根输入 -> 两级同步 -> 四位样点 -> capture_ring -> wave_stream -> frame_tx -> UART
                       |
                       +-> A/B i2c_monitor -> transaction_summary -> 各自FIFO --+
                       +-> A/B line_low_watch -> 故障FIFO --------------------+-> 公平仲裁
                       +-> failover_rules -> 关联/完整读结果FIFO --------------+
```

`task_last_top.v` 只负责复位同步释放和板级连接。`analyzer_core.v`连接模块并维护状态计数。没有按键布防端口，四根总线引脚都只输入，不产生SCL、SDA或ACK。

`i2c_monitor.v`在完整第9位之后公布地址或数据及应答。`valid`只保持一个系统拍；持有的地址字段不能单独当成新事件。解析器不会因RAM冻结或上传结束而清零。未见START的片段不猜地址，读数据末尾的正常主机NACK也不冒充地址NACK。

`transaction_summary.v`在STOP发布一条摘要，保存最多32个数据字节及NACK位图。每路摘要FIFO深32条；A/B故障、关联、完整读和状态也各有独立32条FIFO。满时丢新条目并累计计数；满且同拍出队可以接纳新条目。状态帧分别上报7路丢失和峰值，不能把有限队列称为无限无损日志。

## 自动取证顺序

1. A出现0x6A写地址NACK，或A SCL持续低达到500us，锁存首次故障时刻。等待期间的重复A故障不重启窗口，单独计数。
2. 只接受B的0x68**写**地址ACK。B读地址ACK、其他地址ACK和地址NACK都不匹配。首个匹配与故障间隔≤1ms，发布“地址ACK及时”；到下一间隔仍无匹配，发布“地址ACK超时”。
3. 上一步的成功或超时请求一份故障波形，原因5或4。A首次故障本身只启动等待，不立即冻结。
4. 地址ACK及时之后，继续检查B完整读取。必须是68W ACK、3B ACK、重复START、68R ACK、14字节、前13字节ACK、最后一字节主机NACK、STOP，且STOP在2ms窗口内。否则发布读取不完整或读取超时。
5. 没有进行中的关联时，一次正常B完整读的STOP可以触发原因6的正常波形。故障请求优先，首次被接受的原因保持不变。
6. 收完后半段，RAM冻结；波形末包的UART停止位发完后自动恢复滚动。旧历史作废，下一次早触发按实际历史输出短窗。

地址ACK及时与完整读成功使用两种结果帧，界面分别显示。一次B地址应答不能代表14字节数据已经读完。

## 对齐与边界

同步后的同一组四位样点同时送RAM和解析器，外部输入经过两级同步。事件寄存器携带造成事件的源tick。关联规则用源tick比较；超时判断使用已处理同批样点的时间，给等于截止的ACK优先权。

捕获元数据中的`trigger_tick`表示**捕获控制器实际接受请求并写入的样点**。正常STOP/匹配ACK需要通过事件寄存器传递，本实现通常比源边界迟2个样点。它与事件源tick是两个有明确定义的字段：波形触发索引对应实际写入tick，事件标记应按事件自己的tick换算，不能拿消费者当前计数伪装源时间。电脑也可直接从原始SCL/SDA边沿解码标记。

触发沿写入的点计入后半段。后续还写131071点，写完最后一点才冻结。读物理地址为`first_addr + read_offset`，18位自然绕回；读出按时间顺序，不能直接发物理地址当触发索引。BRAM同步读有一拍返回延迟，上传状态机等`read_valid`再取数据。

BRAM地址和读使能采用同步复位寄存器，数组不清空。复位中可能写无效内容，但有效历史计数清0，解除复位后的第一个样点仍正常保存。这样既避免清空大RAM，也避免异步控制改变BRAM地址的REQP-1839告警。

## 波形、事件和电脑保留

只有一块波形RAM。POST、冻结或上传中再来抓拍请求时，`missed_triggers`增加；协议解析、关联判断、完整读判断和事件排队仍运行。故障结果通过correlation_id与实际波形开始帧关联；没有开始帧时不能凭结果杜撰一份已保存波形。

会话保留首份故障`pinned`供历史接口使用，新增`latest_fault`在原因4/5的完整波形通过校验并归档后更新；`latest_b`只更新为最新含有真实完整B读取的捕获。界面默认跟随`latest_fault`，双击列表或打开归档后手动固定，点击“跟随最新故障”恢复。事件先到而完整波形未到时显示等待提示。每份捕获都写样点BIN、元数据JSON、SHA256，RAM后续复用不会改变已经归档的故障。

串口线程只收字节，解析/校验/归档在线程中完成；UI每100ms取一次合并快照。合并的是界面快照，原始串口字节和事件日志不合并丢弃。UI暂不消费快照时仍能接收全部回放字节。接收字节队列有上限，满时中止并报错，不能继续宣称无损。

画图使用完整样点提取每个实际边沿，保留单样点脉冲；不采用隔N点抽取。绘图只在捕获对象变化时重画，后续最新B更新不重建固定故障的坐标轴。CSV导出在线程中执行；原始数据保存不依赖CSV/PNG完成。

## 串口时间与候选速率

完整波形共1024块；不含实时记录时，开始、块和结束帧合计163952字节。1M、8N1纯线上时间1.63952s。加上读RAM、UART握手和实时帧后略长；正常演示场景目标≤2.5s，**尚待上板实测**。事件持续高压时最多连续2个事件帧后让一块波形，波形仍会前进，但总上传可能超过2.5s。

| 460800 | 108 | 462962.96 | +0.4694% | 约3.54s |

| 1000000 | 50 | 1000000 | 0 | 约1.64s |
| 2000000 | 25 | 2000000 | 0 | 约0.82s |

本轮正式离线实现默认1M。其余为可构建配置，不代表USB串口芯片、驱动和电脑已经长期验证通过。提高波特率能缩短冻结上传，但不能把50MSa/s原始样点连续无间断地送过UART。

## 引脚和MCU对应

沿用阶段九XDC：时钟W19，复位N15，A SCL/SDA为L13/M13，B为M16/M15，TX为N17，3.3V LVCMOS。未使用原人工按键，也没有UART RX约束。约束排除异步输入入口路径，但不排除同步器内部和50MHz核心路径。

当前MCU接口：A为MPU6050、PB10/PB11；B为MPU6500、PB13/PB14；独立总线地址均0x68。M1正常读取、M2 A错地址NACK后读B、M3 A持续拉低后读B。完整读取寄存器起点0x3B，共14字节。MCU初始化的100ms等待不必完整保存在5ms波形中，解析器持续观察后续正常事务即可。

温度与量程换算本版界面默认报告有符号原始值，没有把6050的温度公式套用到6500；物理量换算可在确认对应配置和器件后扩展。数字波形也不用于判定模拟上升时间、振铃或唯一硬件故障根因。
