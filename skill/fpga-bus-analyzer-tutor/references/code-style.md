# 课本代码风格约定

用户于2026-10-02明确要求：将已归纳的课本代码风格写入学习skill，后续编写代码沿用这个风格。本文件是本项目新增和修改Verilog/testbench的默认约定；用户后续明确要求其他风格时按新要求处理。

## 文件组织与排版

- 按“模块与可配置参数 → 输入输出端口 → 参数和内部信号 → 功能逻辑 → 子模块例化”组织。仅保留实际需要的分区；顶层主要承担连接，例化的位置以易读为准。
- 分区使用简明中文注释，如“参数与内部信号”“主逻辑”“子模块例化”；需要明显分隔时用统一的短分隔线。课本的英文标题和长星号线不是功能要求。
- 一行一个端口；按方向、类型、位宽、名称、中文注释对齐，输入和输出适当留空行分组。声明、参数和命名端口连接也竖向对齐。
- 使用统一的4空格缩进。`if/else/case`和赋值条件清楚展开；存在多句或容易增加语句的分支使用`begin/end`。不追求紧凑技巧，不机械复制课本额外的空格。

## 命名与常量

- 自写文件、模块、实例和普通信号优先小写加下划线；模块文件通常与模块同名，仿真顶层用`tb_模块名`，实例可用`模块名_inst`。厂商IP和协议既有接口名称保留。
- 系统接口优先`sys_clk`和`sys_rst_n`；`_n`表示低有效。现有模块已有`clk/rst_n`等清楚名字时保持，不为了风格改接口。
- 计数器用能说明计数对象的`*_cnt`或`cnt_*`，例如`baud_cnt`、`bit_cnt`；同一模块内保持一致。短事件用`*_flag`/`*_pulse`，工作区间用`*_en`，数据有效用`*_valid`，握手采用项目约定的`*_ready`。
- `pi_`、`po_`可用于普通模块输入/输出，沿用已有命名即可；不强制所有端口改名前缀，`sample_data/sample_valid/sample_ready`等明确接口保持原名。
- 参数和状态名称大写：对外可配置值用`parameter`，内部计算值和状态编码优先`localparam`。长数字可用下划线分组，普通数据常量与计数比较尽量明确位宽。
- 注明计数参数表示“周期/样点数量”还是“最后一个计数值”。从0计N次的终值为N-1；不能看到`MAX`就统一减1。参数可变时检查计数器位宽和支持范围，不为通用化增加复杂函数。

## 功能逻辑分块

- 一个时序块优先负责一个寄存器或一项清楚职责，例如分别处理工作使能、时间计数、事件标志、位计数和输出。属于同一操作且关系紧密的寄存器可适当合并；避免巨大的混合逻辑块，也不为拆分而拆分。
- 每个寄存器只能由一个时序块驱动。多个块同时响应时钟，不能按代码先后顺序解释为串行执行。
- 时序逻辑使用`<=`；组合逻辑使用`assign`或`always @(*)`及`=`，并完整赋值。时序块未命中更新条件时可以保持值；组合块不能借未赋值来保存数据。
- 优先用明确的`if/case`、小计数器、简单状态机；不提前加入复杂流水线、宏、通用总线框架或深层抽象。状态机先画图，再写状态与输出；非法状态有明确恢复行为。
- 不固定状态机必须几段或使用独热码：教材简单FSM与I2C编码不同。按任务选择易解释的编码和输出时序，不把两段式必然解释成“时序块加组合块”。

## 标志、使能与数据对齐

- `en`说明哪段时间允许工作；`flag/pulse`说明某个事件到来；`valid`说明数据什么时候可以使用。中文注释明确脉冲宽度、时钟域和对应数据，命名不能代替行为约定。
- 寄存器标志可能让下游下一拍才响应；生成标志、推进索引和更新输出的条件一起检查。不能只抄计数比较值，也不能把非阻塞赋值说成自动等待一个完整时钟周期。
- UART等串行输出应明确什么时候更新、其他时候是否保持。教材TX通过`bit_flag`更新，位计数和输出读取旧索引；若改成每拍按新索引输出，必须重新验证位时间。
- 同一个系统时钟配合采样使能是本分析仪的默认结构。必要输入同步、复位同步释放、RAM读延迟、握手和边界仍按[项目约定](project-context.md)处理；不能为仿照课本排版省略它们。

## 分层中文注释

注释要让基础一般的用户能回答“做什么、何时做、为什么这样做”。按需要写：

1. 模块头：用途、时钟域、复位方式、接口前提和使用限制。
2. 端口及声明旁：方向、位宽、单位、有效电平，以及变量保存什么。
3. 参数旁：含义、计算依据、计数范围和更改时要检查的位宽。
4. 每个逻辑块前：使用课本式“信号名：职责”，说明复位、更新与保持条件。
5. 关键判断处：解释N-1、清零、绕回、第一次触发、一拍事件、读延迟和旧值读取等原因。

示例注释：

```verilog
// baud_cnt：记录当前UART位经过的系统时钟数。
// 从0数到BAUD_CYCLES-1，共BAUD_CYCLES拍；空闲时回零。
// 参数改变后，要检查计数器位宽是否仍能表示终值。

// tx：仅在bit_flag有效时更新当前发送位，其余时钟沿保持。
// 位计数器与本块在同一沿读取更新前的bit_cnt，不能当作先加再输出。
```

不必逐行翻译明显语句，关键地方要详细。改代码后检查注释是否同步更新；端口方向以声明为准，纠正教材或复制过程中的笔误，不照搬错误说明。

## 模块例化与testbench

- 采用`.子模块端口名(当前层信号名)`的命名关联，参数也用命名覆盖。注明容易混淆的方向和数据宽度，检查连接位宽；顶层中间连线使用`wire`。
- testbench自己驱动的输入通常声明为`reg`，接被测模块输出通常用`wire`；被测模块内部`output reg`不要求外部也声明`reg`。
- 将参数/内部信号、初始化和激励、时钟产生、检查与例化分区。先用小参数和确定数据，重复事务按需要用简单`task/for`，避免冗长复制和难懂框架。
- 激励尽量在下降沿改变，检查避开非阻塞更新竞争；初始化不把同一信号分给多个相互竞争的过程。`#`延时、仿真激励和结束语句仅放在testbench。
- 与行为修改相称地检查正常、复位及关键边界；波形之外增加明确的结果比较。尚未运行的验证不写成通过。

## 写完后检查

快速检查端口/信号职责、计数单位和位宽、寄存器唯一驱动、标志与数据对齐、保持与清零、命名连接、中文注释是否准确。对已有文件在本次修改范围内沿用风格，保留已验证的接口，不因统一排版扩展到无关文件。
