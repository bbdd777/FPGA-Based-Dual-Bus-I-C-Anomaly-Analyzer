# 可复用提示词工作流

以下是复用模板，不是历史聊天原文。执行时用本项目真实输入替换方括号，保留实际回答与纠错。

## 接口提取与移植

提示词：请依据[生产源码]和[对应构建日志]提取[模块]接口。逐项列方向、位宽、时钟域、单位、有效条件、复位值和延迟。区分事件源编号、寄存器公布拍、RAM地址和输出索引。对每个结论给出文件及位置；缺失依据写待确认。只整理文档，不修改工程或下载设备。

检查输出：名称与源码一致；valid消费条件有波形或逐拍依据；不能仅据旧文档猜当前行为。再以一个正常例、边界例、复位例检查契约是否自洽。

## 行为与版本不一致

提示词：预期行为是[正式功能]，实测却出现[现象]。请先核对[镜像摘要]、[构建参数]和[实际综合绑定]，给出可以证伪的原因排序及最小观察步骤。不要在未确认参数之前重写RTL；任何硬件动作须在用户授权范围内执行。

检查输出：明确哪项证据排除了哪个假设，修正后同时检查构建、映像和行为，不能把“脚本返回0”当唯一依据。

## 从结果写验收结论

提示词：依据[原始日志与输入数据]、[参考值]、[运行条件]生成验证摘要，分别列编译、模型、RTL、时序和实物结果。每个数值附版本和证据路径，注明本轮重跑或历史引用。列出未测项，不用口头“通过”替代日志。

检查输出：单位一致；不同版本未拼接；CPU观测与外部实测分列；没有把短时压力、ACK或保存截图扩大成完整验收。
